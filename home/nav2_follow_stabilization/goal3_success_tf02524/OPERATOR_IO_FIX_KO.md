# 평가 실행기의 발행·계산 분리

현재 적용: start_evaluation3_ekf_wait.bash. 원본 start_evaluation3.bash는 그대로 보존.

로그 local_avoidance_trial_1794908778365284399.jsonl: PLANNING 중 EKF 대기의 0속도 명령을 보내다가 마지막 제어 로그1794908824544388246과 중단 요청1794908827260052909 사이 약2.716초 공백이 있었다. 드라이버 자체 tick은 약20ms, 발행은1ms 이내, 피드백은 신선했다. 실행기는 MOTOR_STATUS_MISSING_OR_STALE, 드라이버는 COMMAND_TIMEOUT을 보고했다. 모터/엔코더 고장으로 단정할 근거는 없다. 공백이 발생한 정확한 API는 기존 로그로 특정하지 못했다.

적용한 변경:
1. 표시용 상태 발행은 별도 spawn 프로세스. 부모는 최신값 비차단 슬롯에 복사한다.
2. 경로 계산은 ThreadPool 대신 spawn ProcessPool. 같은 원본 planner 함수와 입력/출력을 사용하며 하드웨어/ROS 제어는 하지 않는다.
3. 상태 수신 지연 시 신선한 원시/IMU/스캔으로 속도0 명령을 유지한다. 신선한 원본 status 시각, 진행하는 feedback 수, 동일 epoch, fault 없음, 측정 정지를 안정 확인한 뒤 재개한다. 재arm/오류 자동 해제는 없다.
4. 발행/콜백/그래프/로그 기록의 긴 구간은 slow_operations에 남긴다.

드라이버의 .3초 명령/응답/피드백 감시는 변경하지 않았다. 실제 명령 공급이 계속 끊기면 기존 오류 정지는 남아 있다. 정지5cm/여유10cm/경로/추종/오돔 수학은 원본과 동일함을 바이트 비교로 확인했다.

검사: 상태 대기·복구/장기 손실/옛 상태 시각/하드웨어 오류/epoch 변경/원본 EKF·참조 대기, 실제 별도 프로세스의 경로 함수 실행 및 GIL 지연, 표시 DDS 지연 시험19개 통과. 실제 주행을 도구로 실행하지 않았다.

평가 실행기를 종료하고, COMMAND_TIMEOUT이 남은 드라이버만 재시작한다. 센서/AMCL/중계기는 유지한다. 정지·비무장 상태로 새 기준선을 저장하고 같은 start_evaluation3_ekf_wait.bash를 실행한다. 결과에 isolated_io=true가 있어야 한다.
